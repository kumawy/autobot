# Отправка посылки через Google Sheets

Сотрудник работает в существующей вкладке `Orders`. API Казпочты и отдельная панель не нужны.

1. Найдите оплаченный заказ по `Order ID` и проверьте получателя.
2. После оформления посылки вставьте трек-номер Казпочты в **Z — Трек-номер**.
3. После фактической передачи посылки перевозчику включите **AA — Посылка отправлена**.
4. **AB — Уведомление клиенту** обновляется автоматически. Не вводите туда текст вручную.

Наличие трека без галочки не отправляет сообщение. Галочка без корректного трека показывает ошибку.
Обычная синхронизация изменяет только A:Y; введённые сотрудником Z:AA не перезаписываются.
Защита листа разрешает редакторам таблицы менять только Z2:AA; шапка, финансовые данные и AB защищены.
Владелец Google Sheets технически может менять защищённые ячейки, поэтому не сортируйте физические
строки и не вставляйте/удаляйте их. Используйте представления фильтров. Приложение сверяет Order ID
с закреплённой строкой и отказывается принимать отметки при несовпадении.

## Сообщение клиенту

Русский вариант:

> Заказ {orderId} отправлен через Казпочту 📦
> Трек-номер: {trackingNumber}
> Отследить посылку можно на https://qazpost.kz

Казахский вариант:

> {orderId} тапсырысы Қазпошта арқылы жіберілді 📦
> Трек-нөмір: {trackingNumber}
> Сәлемдемені https://qazpost.kz сайтында бақылай аласыз.

Срок доставки не придумывается. Автоматическое отслеживание прибытия в отделение не включено.
В первой версии один заказ имеет один трек; разделённые отправления требуют отдельного процесса.

## Включение

1. Примените миграции: `npm run db:migrate`, затем соберите приложение `npm run build`.
2. При остановленных записях в таблицу выполните с нужным env-файлом:

   ```sh
   DOTENV_CONFIG_PATH=.env.connected.local npm run sheets:setup -- --shipping
   ```

   Скрипт добавляет Z:AB к существующей структуре A:Y, формат текста для трека, галочки и исключение
   из защиты только для Z2:AA. Существующие заказы и значения не меняются. Несовместимые заголовки,
   неизвестная защита и занятые дополнительные колонки отклоняются. Повтор сохраняет введённые данные.

3. Установите `GOOGLE_SHEETS_SHIPPING_ENABLED=true` вместе с `GOOGLE_SHEETS_ENABLED=true` и
   `GOOGLE_SHEETS_PROVIDER=google`, затем перезапустите приложение и worker. `GOOGLE_SHEETS_RANGE`
   остаётся `Orders!A:Y`: это диапазон **экспорта**, а Z:AB обрабатываются отдельно.
4. Для реального WhatsApp добавьте `order_shipped` в `WHATSAPP_TEMPLATE_REGISTRY`:

   ```json
   {
     "order_shipped": {
       "ru": {"name":"replace_shipping_ru","locale":"ru","parameters":["orderId","trackingNumber"],"available":false},
       "kk": {"name":"replace_shipping_kk","locale":"kk","parameters":["orderId","trackingNumber"],"available":false}
     }
   }
   ```

   Это дополнение к существующему реестру, не замена других назначений. Используйте реальные одобренные
   Meta имена и locale. Тело шаблона содержит два параметра в указанном порядке; URL сайта — статический
   текст. `available=true` выставляется после проверки одобрения. Вне окна общения требуется этот
   шаблон. Для отправки посылки согласие на уведомления и отсутствие отказа проверяются также внутри окна.

## Статусы и повторная обработка

| Значение AB | Что означает |
| --- | --- |
| Ожидает отметки об отправке | Трек введён, галочка ещё не поставлена |
| Ожидает отправки | Уведомление в очереди или безопасном техническом повторе |
| Принято WhatsApp, доставка ещё не подтверждена | API принял сообщение; это ещё не доставка |
| Отправлено / Доставлено клиенту | Получен соответствующий статус от WhatsApp |
| Демо: уведомление записано, WhatsApp не отправлялся | Работает локальный симулятор |
| Ошибка: … | Нужен указанный в ячейке шаг: трек, оплата, согласие или шаблон |
| Проверка: результат отправки неизвестен. Повтор запрещён | Возможна отправка при потере ответа; не повторять вслепую |

Worker читает до 100 закреплённых строк за цикл обслуживания (примерно раз в минуту), затем переходит
к следующей странице. При большом архиве полный обход занимает несколько циклов. HTTP-запросы Sheets
выполняются вне транзакций БД. Недоступность таблицы логируется и не останавливает обработку платежей.
Для работы нужен запущенный worker; выключенный локальный компьютер не отправляет уведомления.

Первое допустимое подтверждение атомарно сохраняет трек, дату и `SHIPPED`, создаёт запись аудита и
единственное задание `shipped:<orderId>`. Повторный запуск и несколько workers не создают новое задание.
Проверяются настоящая оплата, отсутствие финансового hold/incident и уникальность трека. До отправки
WhatsApp эти финансовые ограничения проверяются повторно.

Трек после принятого подтверждения заморожен. Изменение номера или снятие галочки не отменяет физическую
отправку и не создаёт второе сообщение: AB показывает сохранённый трек и необходимость разбора администратором.
Автоматической процедуры исправления уже подтверждённого трека в этой версии нет. До подтверждения трек
можно исправлять свободно. Ошибочный ввод, ещё не принятый приложением, проверяется на следующем обходе.

После устранения причины `BLOCKED` уведомление не возобновляется самопроизвольно: администратор использует
существующий защищённый повтор outbox из [operations.md](operations.md), сверив актуальный заказ и согласие.
`UNKNOWN` без сверки не повторяют. Ошибки delivery receipt не переотправляют автоматически.
