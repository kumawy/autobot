# Браузерный показ с OpenAI и Google Sheets

Пользователь общается с агентом в браузере, оформляет заказ и нажимает тестовую оплату. Вопросы о товаре обрабатывает OpenAI; после подтверждённого mock callback оплаченный заказ сохраняется в PostgreSQL и отправляется в Google Sheets. WhatsApp и Telegram можно подключить следующим этапом. Каталог и условия пока демонстрационные, настоящих списаний нет.

## Запуск

Нужен Node.js 24.21.0. После `npm ci` выполните:

```sh
npm run demo:connected
```

Первый запуск создаёт приватный `.env.connected.local` и останавливается, если в нём нет `OPENAI_API_KEY`. Заполните ключ локально, затем повторите команду. Файл исключён из Git; не отправляйте его в репозиторий или переписку. По умолчанию выбрана модель `gpt-4.1-mini`.

Откройте **http://localhost:3001**. Команда запускает PostgreSQL на `127.0.0.1:55433`, применяет миграции и запускает HTTP-приложение с worker. База находится в `.local/postgres-connected`; данные сохраняются после остановки Ctrl+C и следующего запуска. Обычное автономное демо на портах 3000/55432 использует другую базу.

Режим задаётся независимо от транспорта:

```dotenv
INTEGRATION_MODE=demo
AI_PROVIDER=openai
OPENAI_MODEL=gpt-4.1-mini
PAYMENT_PROVIDER=mock
GOOGLE_SHEETS_PROVIDER=google
GOOGLE_SHEETS_ENABLED=false
TELEGRAM_ENABLED=false
MANAGER_HANDOFF_ENABLED=false
```

Пока Google не настроен, `GOOGLE_SHEETS_ENABLED=false` честно отключает экспорт. Оплаченные заказы сохраняются в базе; интерфейс не показывает ложный успешный экспорт.

## Подключение Google Sheets

Нужна таблица, принадлежащая вашему Google-аккаунту, и JSON-ключ сервисного аккаунта Google Cloud с включённым Google Sheets API. Сам сервисный аккаунт не должен создавать файл в своём Drive. Поделитесь только нужной таблицей с его `client_email`, дав доступ редактора.

Сохраните JSON в `.local/secrets/google-service-account.json`, ограничьте права файла `chmod 600` и укажите в `.env.connected.local`:

```dotenv
GOOGLE_APPLICATION_CREDENTIALS=.local/secrets/google-service-account.json
GOOGLE_SHEETS_OWNER_EMAIL=your-google-account@example.com
GOOGLE_SHEETS_SPREADSHEET_ID=the-id-between-d-and-edit-in-the-sheet-url
GOOGLE_SHEETS_RANGE=Orders!A:Y
```

Путь к JSON имеет приоритет над парой `GOOGLE_SERVICE_ACCOUNT_EMAIL` / `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`. Ошибка чтения или формата файла не приводит к незаметному использованию другого ключа. Ключи не выводятся в логи или интерфейс.

При остановленном приложении и без одновременного ручного редактирования таблицы выполните:

```sh
DOTENV_CONFIG_PATH=.env.connected.local npm run sheets:setup
```

Команда создаёт отсутствующую вкладку `Orders` либо готовит пустой шаблон: проверяет 25 заголовков, закрепляет первую строку и защищает вкладку, оставляя редактирование владельцу и сервисному аккаунту. Вкладка с заказами проверяется без изменения данных; несовместимая структура или чужая защита блокируют настройку. Не сортируйте, не вставляйте и не удаляйте физические строки `Orders`: приложение привязывает заказ к постоянной строке.

Скопируйте выведенный `GOOGLE_SHEETS_SHEET_ID` в профиль и включите:

```dotenv
GOOGLE_SHEETS_ENABLED=true
```

Перезапустите `npm run demo:connected`. Для показа оформите новый заказ. Ранее заблокированные задания не запускаются одним переключением настройки: повтор запускается через защищённые средства управления очередью, описанные в [operations.md](operations.md).

## Как показать результат

1. Откройте чат на `localhost:3001`, выберите русский или казахский язык и спросите о музыкальной шкатулке. Метка OpenAI показывает выбранный провайдер; успешный ответ проверяется отдельно от конфигурации.
2. Нажмите «Заказать», пройдите форму с вымышленными данными и подтвердите заказ.
3. Нажмите тестовую оплату. Подписанный mock callback должен перевести заказ в `PAID`.
4. Дождитесь подтверждённой записи Google Sheets в карточке заказа. По ссылке откройте `Orders`: там должна быть одна строка с тем же Order ID и суммой.
5. Повторное подтверждение того же платежа должно обновлять ту же строку, а не создавать дубль.

Публичное размещение и Meta требуют отдельного staging/live-профиля и HTTPS: см. [STAGING_DEPLOYMENT.md](STAGING_DEPLOYMENT.md). Этот браузерный запуск доступен только локально. Подключение реальных платежей также остаётся отдельным этапом.
