# Отдельная проверка OpenAI

Команда `test:openai` выполняет один небольшой реальный запрос к OpenAI и выводит только ответ модели либо контролируемый код ошибки. Она не запускает сервер, worker, WhatsApp, Freedom Pay или Google Sheets и не требует настроек этих сервисов.

В локальном `.env.staging.local` должны быть `NODE_ENV=development`, `OPENAI_API_KEY` и `OPENAI_MODEL=gpt-4.1-mini`. Ключ вводится только в этот закрытый файл; не публикуйте его и не передавайте через аргументы команды. Имя модели скрипт читает из `OPENAI_MODEL`, без запасной модели в коде. [Официальная страница GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) описывает поддержку Responses API.

```sh
chmod 600 .env.staging.local
DOTENV_CONFIG_PATH=.env.staging.local npm run --silent test:openai
```

Запрос просит ответить `OK`, но текст модели может отличаться: успешная проверка означает завершённый непустой ответ, а не точное совпадение со словом. Без npm-команды можно выполнить `DOTENV_CONFIG_PATH=.env.staging.local npx tsx scripts/test-openai.ts`. Явно заданный отсутствующий env-файл завершает проверку с ошибкой; скрытого переключения на `.env` нет. Уже экспортированные переменные окружения имеют приоритет над значениями файла.

Скрипт разрешён только при `NODE_ENV=development` (также значение по умолчанию, если переменная отсутствует). При `production` или `test` запрос не выполняется. Запрос использует официальный Node SDK, [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses), `store:false`, максимум 16 выходных токенов, тайм-аут 10 секунд и `maxRetries:0`. Отправляется только фраза `Ответь одним словом: OK`; каталог, переписка и персональные данные не передаются. Логи SDK отключены.

При успехе код завершения — `0`; при ошибке — `1`. В stderr выводится один код без ключа, HTTP-заголовков, тела ошибки или стека:

| Код | Что проверить |
|---|---|
| `DEVELOPMENT_ONLY` | Для этой отдельной проверки требуется development-окружение. |
| `OPENAI_ENV_FILE_UNAVAILABLE` | Указанный `DOTENV_CONFIG_PATH` существует и читается. |
| `OPENAI_API_KEY_MISSING` / `OPENAI_MODEL_MISSING` | Значение заполнено в выбранном файле или окружении. |
| `OPENAI_AUTHENTICATION_FAILED` / `OPENAI_ACCESS_DENIED` | Действительность ключа и доступ API-проекта. |
| `OPENAI_MODEL_NOT_FOUND` | Имя модели и её доступность для проекта. |
| `OPENAI_RATE_LIMIT_OR_QUOTA` | Квота, лимиты и состояние оплаты API-проекта. |
| `OPENAI_REQUEST_TIMEOUT` / `OPENAI_NETWORK_UNAVAILABLE` / `OPENAI_SERVICE_UNAVAILABLE` | Соединение и доступность сервиса; автоматического повторного запроса нет. |
| `OPENAI_RESPONSE_INCOMPLETE` / `OPENAI_RESPONSE_EMPTY` / `OPENAI_REQUEST_FAILED` | Ответ не подтвердил успешную проверку; исходная ошибка намеренно не печатается. |

Успешное завершение подтверждает только возможность выполнить минимальный запрос выбранной моделью. Работа консультации с инструментами, RU/KK, ограничением данных и handoff проверяется отдельно. Настройки сервиса `OpenAiService` сохраняют строгий список инструментов, запрет финансовых действий и безопасную передачу менеджеру при ошибке.

1 октября 2026 года выполнена отдельная реальная staging-проверка модели `gpt-4.1-mini`: код завершения `0`, ответ `Понял`. Это подтверждение связи с API; проверки остальных интеграций и полного сценария консультации этим запуском не заменяются.

Обычные тесты работают без сети и реальных ключей:

```sh
npx vitest run tests/unit/openai-connectivity.test.ts tests/unit/ai.test.ts
```

SDK в них подменён; дополнительные проверки CLI выполняют только ветки отказа до запроса. Живой `test:openai` не входит в `npm test` и запускается отдельно при подготовленных credentials. Время и результат фактического staging-запуска фиксируются отдельно от результатов offline-тестов.
