# WhatsApp Business через QR-код на Railway

## Режим работы

`WHATSAPP_TRANSPORT=baileys` подключает номер как связанное устройство WhatsApp Web. Документы бизнеса и подписка WhatsApp-провайдера для этого не нужны. Это неофициальная библиотека: возможны отключения и блокировка номера. Первую проверку проводите на тестовом номере. Railway и AI оплачиваются отдельно.

Существующие сценарии, OpenAI, оформление заказа, оплаты, Google Sheets и Telegram используют прежние сервисы. Транспорт `cloud` для Meta API также сохраняется.

В режиме Baileys `npm start` запускает **HTTP, worker и подключение номера в одном процессе**. Второй сервис worker создавать не нужно; `npm run worker` намеренно отклоняется. PostgreSQL выдаёт владельцу сессии lease на 60 секунд, который обновляется каждые 15 секунд. Второй процесс ждёт освобождения сессии. При потере lease подключение закрывается.

## Настройка Railway

1. Создайте Railway-проект с PostgreSQL и одним сервисом приложения из репозитория.
2. Используйте [railway.json](../railway.json): Dockerfile, `npm start`, предварительная миграция `npm run db:migrate`, проверка `/ready`, одна реплика, Serverless выключен. Политика `Always` требует соответствующего платного плана Railway.
3. Создайте публичный домен приложения. Запишите его HTTPS origin без пути в `APP_BASE_URL`.
4. Перенесите настройки из [baileys.env.example](../baileys.env.example) в Railway Variables. `DATABASE_URL` задайте ссылкой на PostgreSQL проекта. Для Railway PostgreSQL `DIRECT_URL` можно оставить пустым; для существующей Supabase сохраните правила direct/session URL из текущих инструкций миграций.
5. Сгенерируйте **три независимых** случайных значения для `WHATSAPP_AUTH_ENCRYPTION_KEY`, `ADMIN_TOKEN` и `MOCK_PAYMENT_SECRET`. Для каждого значения отдельно выполните у себя:

```sh
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"
```

Ключ шифрования — 64 hex-символа. Остальные секреты — минимум 24 символа. Копируйте результат только в соответствующую переменную; не добавляйте секреты в репозиторий. **Сохраняйте ключ шифрования при обновлении Railway**: смена ключа сделает прежнюю авторизацию нечитаемой. Для восстановления резервной копии базы нужен тот же ключ.

6. Укажите `WHATSAPP_EXPECTED_NUMBER` — международный номер цифрами, без `+`. Если QR отсканирован другим аккаунтом, связь закроется.
7. Укажите свои `OPENAI_API_KEY` и `OPENAI_MODEL`. Для первой проверки без AI можно временно задать `AI_PROVIDER=demo`, чтобы использовать существующий детерминированный ответчик.
8. Для пробного запуска оставьте `NODE_ENV=development`, `INTEGRATION_MODE=staging`, `PAYMENT_PROVIDER=mock`, `DEV_ROUTES_ENABLED=false`. **Это тестовая интеграция, без реальной оплаты.** В Dockerfile исходно задан production: обязательно переопределите `NODE_ENV` в Railway Variables. Публичный локальный симулятор в staging не регистрируется.
9. Разверните приложение, откройте `https://ВАШ-ДОМЕН/whatsapp/connect`, введите `ADMIN_TOKEN`.
10. На телефоне: WhatsApp Business → Связанные устройства → Привязать устройство. Отсканируйте QR и дождитесь «WhatsApp подключён». Проверьте показанный номер.

Приложение принимает `PORT` от Railway и слушает `HOST=0.0.0.0`. `/ready` проверяет базу, а не наличие связанного телефона: иначе при первом развёртывании было бы невозможно открыть QR. Состояние связи видно на странице подключения и в защищённом `/admin/whatsapp/status`; heartbeat worker — в `/admin/status`.

## Сессия и восстановление

Авторизация и Signal-ключи сохраняются в таблице `WhatsAppAuthRecord` PostgreSQL с AES-256-GCM; ключ находится в переменной окружения. Отдельный файловый volume для Baileys не нужен. Миграция добавляет две таблицы и сохраняет существующие заказы.

Обычный перезапуск использует сохранённую сессию. Временный разрыв запускает повторное подключение с увеличением паузы до 30 секунд. При выходе из аккаунта попытки прекращаются: нажмите «Восстановить подключение» и отсканируйте новый QR. Только явное восстановление после `logged_out` или `number_mismatch` очищает старую авторизацию; переписка и заказы сохраняются.

Пока связи нет, WhatsApp-задания ждут в базе, не расходуя лимит попыток. Неоднозначная ошибка после начала отправки даёт `UNKNOWN`: такое сообщение не отправляется повторно автоматически. Разберите его через существующую диагностику, чтобы избежать дублей.

Если Telegram включён, состояния `logged_out`, `number_mismatch` и `storage_error` создают уведомление в рабочий чат, не чаще одного на состояние в час. Без Telegram контролируйте страницу и журналы Railway. Включите резервное копирование PostgreSQL и мониторинг heartbeat.

## Менеджер и бот

- Ручной ответ с телефона сохраняется как исходящее сообщение менеджера и переводит **этот** разговор в `HUMAN_HANDOFF`.
- Собственные отправки бота идентифицируются по заранее сохранённому ID и не вызывают паузу, даже если echo приходит раньше подтверждения отправки.
- Ожидающие консультационные ответы отменяются. Если AI ещё готовит ответ, изменение версии диалога не позволит его отправить.
- Уже начатую внешнюю отправку нельзя отменить задним числом. Перед ручным ответом явно нажмите «Поставить на паузу» на странице подключения.
- На странице отображаются последние 100 клиентов. «Вернуть боту» закрывает обращение и восстанавливает допустимый этап с учётом заказа и оплаты.
- Без Telegram управление с телефона и страницы работает. Существующий Telegram-мост `/claim`, Reply, `/close` остаётся доступен при отдельной настройке.
- Финансовые callback и разрешённые служебные уведомления работают независимо от паузы AI.

## Меню и ограничения

По умолчанию кнопки и списки отправляются как текст с нумерованными вариантами. Клиент отвечает цифрой; система сопоставляет её с одноразовым action token последнего отправленного меню. Сохраняются проверки клиента, версии, срока и факта использования. Ответ с цитатой на устаревшее меню проходит существующую проверку устаревших действий.

`WHATSAPP_BAILEYS_BUTTONS=true` включает экспериментальные нажимаемые кнопки в коротких меню (1–3 варианта), включая «Қазақша»/«Русский». Используется native-flow `quick_reply` через `relayMessage`; параметры нажатия обрабатываются теми же одноразовыми токенами, что и выбор цифрой. Нумерация сохраняется в тексте сообщения. Списки и более длинные меню остаются текстовыми. При неизвестном результате отправки сообщение не повторяется автоматически. Совместимость отображения проверяйте на телефонах клиентов: успешная передача не доказывает, что WhatsApp показал кнопки. Если они не отображаются, задайте `WHATSAPP_BAILEYS_BUTTONS=false` и перезапустите приложение для возврата к обычным текстовым меню. Обновлять библиотеку или устанавливать сторонний fork не требуется. Используемый формат описан в [реализации native-flow для Baileys](https://github.com/zqdevelopers/zq_baileys_helper).

Поддержаны входящие текстовые сообщения, существующий обработчик неподдерживаемых медиа, исходящие текст и изображения. Голосовые не расшифровываются. Группы, статусы, рассылки и импорт старой истории не обрабатываются. История до первого связывания не запускает бота; повторы новых сообщений дедуплицируются.

В Baileys нет механизма одобренных Cloud API-шаблонов: они отклоняются. Ограничение 24-часового окна Cloud API применяется только к транспорту `cloud`. В Baileys сохраняются запреты устаревших AI/операторских ответов и проверки согласия на инициативные служебные уведомления. Рассылки в эту доработку не входят.

WebSocket не даёт гарантий повторной доставки webhook официального API. При длительном сбое базы приём может прерваться; после восстановления проверьте переписку и очередь. Данные до первого связывания не импортируются автоматически.

## Локальный запуск

Railway, Docker, публичный домен и tunnel для локальной переписки не требуются. Используйте Node.js из `.nvmrc`:

```sh
npm ci
npm run whatsapp:local
```

1. Откройте `http://localhost:3002/whatsapp/connect` на этом ноутбуке.
2. Введите значение `ADMIN_TOKEN` из `.env.baileys.local`. Файл создаётся автоматически с правами `0600`, исключён из Git; секреты не выводятся в терминал. Не отправляйте файл или ключи другим людям.
3. В WhatsApp Business на телефоне откройте «Связанные устройства» → «Привязать устройство», отсканируйте QR и дождитесь подключения.
4. Напишите на подключённый номер с другого номера и проверьте ответ. Ручной ответ с телефона ставит этот разговор на паузу; вернуть клиента боту можно на странице подключения.
5. Остановка — Ctrl+C. Повторный `npm run whatsapp:local` сохраняет авторизацию и заказы. Для переноса сохраняйте базу **вместе** с ключом шифрования из env-файла.

Первый запуск создаёт отдельные `.env.baileys.local` и `.local/postgres-baileys`, PostgreSQL на `127.0.0.1:55435`, применяет миграции и запускает единый HTTP/worker/WhatsApp-процесс. Старые базы `.local/postgres*` и env-файлы не изменяются. Если порты заняты, второй запуск отклоняется. В существующем профиле можно изменить `PORT` и соответствующий `APP_BASE_URL=http://localhost:PORT`; адрес привязки остаётся `HOST=127.0.0.1`.

В новых локальных профилях включены экспериментальные кнопки (`WHATSAPP_BAILEYS_BUTTONS=true`). В старом профиле добавьте переменную вручную; существующие файлы команда не перезаписывает.

Если в `.env.connected.local` уже заданы ключ и модель OpenAI, первый запуск переносит только настройки AI и основные данные бизнеса в новый приватный профиль. Google Sheets и Telegram отключены, чтобы новая база не записывала строки в существующую таблицу. При отсутствии ключа/модели включается `AI_PROVIDER=demo`; для настоящего AI задайте `AI_PROVIDER=openai`, `OPENAI_API_KEY` и `OPENAI_MODEL` в `.env.baileys.local` и перезапустите команду. При повторном запуске файл и секреты не перезаписываются. При желании задайте `WHATSAPP_EXPECTED_NUMBER` цифрами без `+` для проверки номера при сканировании.

Режим остаётся `staging` с **тестовой оплатой**. Ссылки `http://localhost:3002/mock-payment/...` открывайте на ноутбуке: на телефоне `localhost` указывает на сам телефон. Для доступных клиентам ссылок понадобится публичный HTTPS origin и обычный запуск с соответствующей базой. Локальный HTTP разрешён только Baileys с loopback-адресом и loopback-привязкой; требования Meta Cloud API и production не меняются.

Бот работает, пока ноутбук включён, подключён к интернету, не спит и команда запущена. Чтобы получить круглосуточную работу без ноутбука, позже перенесите приложение и PostgreSQL на сервер.

Демо `npm run demo` сохраняет прежний режим, с `WHATSAPP_TRANSPORT=cloud` по умолчанию и без настоящих WhatsApp-отправок.

Для реальной оплаты сохраняется существующий production-процесс: `NODE_ENV=production`, `INTEGRATION_MODE=live`, Freedom Pay с выключенным тестовым режимом, утверждённые бизнес-данные и проверенные интеграции. Замена транспорта сама по себе не включает оплату. `npm run check:production` учитывает Baileys: вместо Meta-токенов и шаблонов требуется проверка QR и ручного управления.

## Проверка рабочего подключения

1. С другого номера получите меню и выберите язык цифрой.
2. Пройдите существующий сценарий до mock-оплаты; реальные деньги не списываются.
3. Ответьте с телефона: этот диалог должен перейти к менеджеру, другой клиент продолжает общаться с ботом.
4. Верните диалог боту через страницу.
5. Перезапустите Railway и проверьте сохранение авторизации и состояний.
6. Отключите связанное устройство и проверьте новый QR после явного восстановления.
7. Выключите ноутбук и проверьте ответ с Railway.

Автоматические проверки используют настоящую временную PostgreSQL и подменённый socket. Они не заменяют проверку доставки на реальном номере.
