# OpenAI и демонстрационный консультант

Локальный режим использует `DemoAiService`: работает без сети, API-ключа и расходов. Он отвечает на основные вопросы по проверенному JSON-каталогу на русском и казахском. Нераспознанный вопрос или отсутствующие условия передаются менеджеру. Это детерминированный симулятор консультанта; качество свободного диалога проверяется отдельно после подключения OpenAI.

Для живой интеграции задайте `INTEGRATION_MODE=live`, `OPENAI_API_KEY` и `OPENAI_MODEL` в локальном `.env` или в хранилище секретов сервера. Режим `live` также включает остальные реальные интеграции и требует их credentials согласно `.env.example`; для отдельной проверки AI можно создать `OpenAiService` в тестовом скрипте. Имя модели не зашито в коде: выберите доступную вашему API-проекту модель с поддержкой Responses API и function calling. Установите лимит расходов в API-проекте и проверьте несколько сценариев в тестовом окружении. Не публикуйте ключ и не передавайте его в клиентский интерфейс.

Адаптер использует официальный Node SDK, `responses.create`, `store: false`, JSON-схемы `strict: true` и запрет дополнительных аргументов. Результаты инструментов возвращаются с исходным `call_id`; все output items, в том числе reasoning items, сохраняются в пределах одного вызова для продолжения цикла. Это соответствует [официальной документации OpenAI по function calling](https://developers.openai.com/api/docs/guides/function-calling) и [переходу на Responses](https://developers.openai.com/api/docs/guides/migrate-to-responses).

Разрешены только четыре чтения каталога (`get_product_info`, `list_available_discs`, `get_delivery_info`, `get_payment_info`) и три запроса интерфейсу (`show_main_menu`, `start_order`, `request_human_handoff`). Последние возвращают действие машине состояний. AI не получает экземпляр БД, платёжного сервиса или доступа к изменению цены, скидке, оплате и возврату. Неизвестное имя инструмента либо лишний аргумент завершают ответ передачей менеджеру.

Один ответ ограничен тремя запросами, общим тайм-аутом 15 секунд в приложении (12 секунд по умолчанию у адаптера) и 700 выходными токенами на запрос. Автоматические повторы SDK отключены. При тайм-ауте, ошибке API, неполном ответе, превышении лимита, подозрительном подтверждении оплаты или неподтверждённой цене разговор передаётся менеджеру. Тайм-аут можно изменить через аргумент `timeoutMs` при создании сервиса. Цена всегда берётся из конфигурации приложения.

В AI передаются текущий вопрос и не более шести коротких сообщений консультации. Историю формы заказа, адреса, контакты и данные получателя передавать нельзя. Адаптер дополнительно отфильтровывает распространённые шаблоны телефонов, email, адресов и платёжных реквизитов; секреты типичного вида заменяются маркерами. Это дополнительная защита, а не гарантия распознавания любых персональных данных в произвольном тексте. Ошибки SDK с исходными запросами не логируются. `store: false` отключает хранение объектов Responses для последующего извлечения; требования к обработке данных API нужно отдельно сверить с настройками вашего проекта.

Каталог находится в `data/product.ru.json`, `product.kk.json`, `discs.json` и двух файлах FAQ. `null` означает неизвестные данные. Демонстрационные позиции помечены `demo: true`; реальные фото пока отсутствуют. Перед эксплуатацией замените эти данные и убедитесь, что `catalog.productionReadiness()` возвращает `ready: true`. Не подменяйте отсутствующие условия предположениями.

Проверки без сети: `npx vitest run tests/unit/ai.test.ts tests/unit/catalog.test.ts`. Они покрывают RU/KK, неизвестные условия, защиту цены и платежа, список доступных мелодий, строгие инструменты, продолжение Responses, ограничения цикла, ошибки и фильтрацию персональных данных. Живой вызов OpenAI без предоставленных credentials не проверялся.
