# Проверки проекта

## Staging integrations · 1 октября 2026 года

Ветка `feat/staging-integrations`, macOS, Node.js **24.21.0**. Сохраняется исходный v1.1; новых схем или разрушительных миграций нет.

- `npm install` — успешно, audit сообщил 0 уязвимостей.
- `npm run db:validate`, `typecheck`, `lint`, `build` — успешно.
- Собранное HTTP-приложение запущено на отдельном локальном порту: `/health` вернул 200 и `database:connected`, HTML симулятора — 200. Проверочный процесс остановлен после проверки.
- `npm run test:unit` — **288 тестов в 15 файлах**; `npm run test:integration` — **83 теста в 5 файлах**. Всего **371**.
- `db:check` с локальной PostgreSQL — `Database connection: OK`; staging-конфиг с незаполненным паролем корректно отклонён без обращения к Supabase и без вывода URL/пароля.
- `test:openai` запущен отдельно с `gpt-4.1-mini`: реальный completed-ответ «Понял», exit 0. Это проверка доступа, не live-проверка всех tools или качества RU/KK. Обычные тесты внешние API не вызывают.
- Staging integration: настоящий PostgreSQL, все 5 существующих миграций, настоящий WhatsApp HTTP-адаптер с подменённым `fetch`; signed webhook → durable ACK → worker → сохранённый исходящий ID. Проверены дубли, RU/KK, восстановление acknowledged inbox/заказа после перезапуска, 24-часовая mock-ссылка, PAID ровно один раз и доставка по callback.
- Проверено отключение Sheets/Telegram без ложного SYNCED/отправки, сохранение заказа при недоступном менеджере и возврат старого HUMAN_HANDOFF к прежнему шагу. Отложенные bridge-сообщения блокируются. Создание/сверка платежей запрещены при несовпадении provider/merchant.
- `.env.staging.local` исключён из Git, права `0600`; приватные env-файлы в текущем индексе и истории не найдены. Проверка исходников на длинные проектные OpenAI-ключи и PEM private key не выявила совпадений.
- Prisma config проверен в отдельной структуре файлов runtime Docker-образа. Сам Docker не установлен, контейнерная сборка/запуск не проверялись.

**Не выполнено:** подключение/миграции в Supabase, реальный WhatsApp диалог и размещение на публичном сервере. Причины: пароль БД остаётся заглушкой; не заполнены Meta credentials и публичный HTTPS origin. Freedom Pay остаётся mock; настоящих платежей не было. Инструкции: [staging](STAGING_DEPLOYMENT.md), [Meta](META_WHATSAPP_DEMO.md), [OpenAI](OPENAI_STAGING.md).

## Ручная проверка интерфейса

В Safari на настольном экране пройдены первый вопрос и выбор языка, заказ RU, показ privacy notice и отдельное согласие, выбор диска, доставка/итог, заморозка суммы и тестовая оплата. Фраза «я оплатил» оставляет PAYMENT_PENDING; подписанный mock callback даёт PAID, подтверждение клиенту и завершённые задания Sheets/Telegram.

Проверены обращение менеджеру, claim 1001, Reply в нужный диалог, close, повторное обращение и явный возврат клиента к боту. STOP отключает инициативные уведомления, сохраняя PAID. Исправлены подписи действий, автор ответа менеджера и отображение статуса старого ticket.

Для исходного patch v1.1 мобильный viewport отдельно не проверялся. Docker на этой машине отсутствует, поэтому контейнерная сборка и `docker compose up` не выполнялись. В том этапе реальные Meta, OpenAI, Freedom Pay, Google Sheets и Telegram не подключались; настоящих списаний и сообщений не было. Требования к проверке аккаунтов перечислены в [production-readiness.md](production-readiness.md).
